# Voice 对 Pocket 回复的复核

日期：2026-10-02。依据 Pocket 的 `voice-api-response-2026-10-02.md`。

结论：接受对方方向，没有发现需要推翻的产品边界。下文是定稿前的复核记录；权威契约为 [移动接口 V1](mobile-api-v1.md)，实施后的部署及证据分别见 [移动入口部署](mobile-deployment.md) 和 [验证记录](validation.md)。无需再次协商已确定的原则，首版为 PC + 手机共享 R2T2。

## 需要补明的五点

### 1. 区分已固定、已收到和已填入

服务端固定文字不等于手机已经收到，更不等于已经填入目标框。建议手机分别维护收到的固定全文和已成功填入的位置，继续保留目标框变化保护。

正常 `finish` 或 PC 切换时，连接仍可用则服务端发送最终固定全文及结束原因。断网时不能保证手机收到最终事件；手机只能保证保留本地已经收到的固定文字，并提示尾部可能未完成。不要把“所有断线均收到结束事件”作为验收条件，也不能把未收到的服务端结果报告为已经保存。

### 2. V1 使用累计固定全文与会话内事件序号

建议服务器输出 `session_id`、`model_generation`、`seq`、累计固定 `text`、可变 `pending`；服务实例身份和代次在开始时绑定。`seq` 定义为会话内递增的事件序号，不是字数或文字版本；候选变化但固定文字未变时，也可产生新事件。

客户端只接受当前会话与代次的事件。已处理的旧序号忽略，新固定全文必须以本地已接受的固定全文为前缀；仅追加新增部分。前缀冲突要停止自动填入并保留本地内容，不能覆盖用户原文。最终事件也携带累计全文，即使全文没变也使用新序号，防止将同一段当成新的增量重复填入或漏处理会话结束。

上述机制用于应用层去重，不承诺外部输入框在应用崩溃等任意故障下都能实现严格的 exactly-once。重启后不能未经目标核对自动补贴旧文字。

### 3. V1 断线结束旧会话，不自动回放旧音频

推荐第一版不恢复旧 ASR 状态。断线、取消或模型代次变化后，客户端关闭旧会话的文字提交通道，丢弃迟到事件，保留本地固定文字；用户重试时查询当前能力并创建新会话。

新会话不自动重发旧音频，不自动重贴原有文字，也不因连接恢复而自动开始录音。状态诊断可有界重试；认证失败、模式不支持、PC 未加载及模型变化应分别提示。以后若需要无缝续传，再单独设计音频确认、结果重放和恢复窗口。

### 4. 音频发送不能等待上一包识别结果

确认基础格式可沿用二进制 `16 kHz / 单声道 / PCM16 小端`。正常传输建议每包 80–160 ms；最终帧限制、流控字段和计量单位在正式协议中给出，不能把建议值当作已部署限制。

手机和 PC 都应独立执行音频发送与文字接收。不能采用“发送一包 → 等识别返回 → 发下一包”，否则推理或网络延迟会阻塞采集侧，并掩盖服务器积压。

服务端接收许可/已接收进度与 ASR 文字结果分开。客户端缓冲和服务端每会话队列都有上限；恢复发送只按流控规则推进，不补发已接收音频。超限不能无限缓存或静默丢音频，应明确结束受影响会话并保留固定文字，不影响另一端。暂停/恢复阈值及恢复后的发送速率由实际双流测试确定。

### 5. IP 诊断与 TLS 身份不能混为一谈

接受以完整 Tailnet DNS 名和 HTTPS/WSS 为正常识别入口。裸 IP 可以用于网络诊断；若要作为 HTTPS/WSS 主机，必须有可验证且匹配的证书身份方案。不能继续使用仅对 DNS 名有效的证书，却跳过 IP 主机名校验。

建议第一版正式 ASR 地址使用 DNS 名，裸 IP 仅诊断；若 Pocket 要支持 IP 手动连接，另行明确证书/SNI/服务器名规则。证书错误须单独提示，TCP 超时只能按可确认的信息说明连接失败，不能据此断言 Tailscale 未开启。

## 并发研究给 Pocket 的影响

- 主线为同一份 R2T2 权重、每端独立状态、vLLM AsyncLLM 连续批处理。每端最多一个在途模型步骤，不同端独立完成；模型内部 token 中间结果不直接填入输入框。
- 已完成官方源码核对和纯 CPU 模拟的双流状态隔离演算；尚未实施异步适配或验证 GPU 双流性能。研究细节见 [并发技术研究](concurrency-research-2026-10-02.md)。
- 接口应支持持续双向消息及本端取消，不绑定“一包音频必对应一条立即文字”的假设。`flush` 只等待本端此前的音频，不能成为两端共同等待的屏障。
- 共同验收应补充：断线时没有 final 仍保留本地固定文字；重复事件/迟到事件不误填；慢客户端与缓冲超限不影响另一端；发送端按真实采集时钟送音频，不能靠等服务器结果放慢回放而隐藏积压。
