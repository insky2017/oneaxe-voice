# 使用与鉴权

## 开始使用

1. 连接系统 Tailscale，在设置中填写服务器 `https://<主机名>.ts.net:<端口>`。
2. 管理员为本设备签发独立凭据，填入设置并保存。每台 Linux 电脑与安卓端分别使用自己的凭据。
3. 在服务器原有托盘中选择 **R2T2**，等模型就绪，再在客户端点“测试连接”。现有远端 V1 仅支持 R2T2；选择 Qwen 时客户端会提示模式不支持，不会替服务器切换或加载模型。
4. 选择麦克风，切到需要输入文字的窗口，按 F9 开始，再按 F9 停止。停顿时会补齐当前句。
5. 取消只结束本客户端会话。目标窗口变化后，本轮仅复制，避免输入到错误位置。

录音或收尾时，“复制并暂停自动输入”会先完成正在执行的交付，再复制当前已确认全文；录音继续，本轮后续文字只更新全文剪贴板。这样手动复制不会夹进自动粘贴操作。结束后按钮恢复为“复制”。下一轮重新按自动输入设置工作。

快捷键可修改。冲突时提示，不覆盖其他程序的键位。Wayland 首版使用窗口按钮与手动复制；自动输入以 X11 为验收对象。

## 鉴权的中间过程

Tailscale 决定电脑能否到达服务器；设备令牌决定这个客户端是否有识别权限。

1. 管理员在服务器本机用已有 `oneaxe-voice device issue` 签发令牌。服务器保存令牌摘要和设备权限，不保存令牌原文。
2. 通过可信通道把令牌交给对应电脑。可使用 SSH 标准输入导入，避免出现在命令参数或日志中。
3. App 按服务器地址将令牌存入 Secret Service 系统密钥环。普通配置文件没有令牌。更换服务器地址后，不会向新服务器发送旧凭据。
4. 能力查询与 WSS 握手都在 TLS 校验成功后携带 `Authorization: Bearer <device-token>`。令牌不进入 URL。连接不跟随重定向。
5. 服务端检查摘要、是否吊销，以及 `voice.mobile.read` / `voice.mobile.stream` 权限。开始识别时再检查模型代次和远端名额。
6. 丢失设备时，管理员吊销对应凭据；其他设备凭据不受影响。轮换后，将新令牌重新存入对应电脑。

本轮无需新增认证接口或修改服务端代码。设备凭据没有模型管理权限。公网入口及网络安全部署另行安排。

## 命令行配置

```bash
oneaxe-voice-linux --configure https://rtx4090.nase-stairs.ts.net:8097
oneaxe-voice-linux --check
oneaxe-voice-linux --shortcut F9
oneaxe-voice-linux --help
```

`--import-token` 从标准输入读取凭据。不要将令牌写在命令参数、脚本、仓库或截图中。通过 SSH 导入时，需要连接用户现有图形会话的 D-Bus，密钥环应已解锁。

无效凭据显示鉴权失败；容量不足时不录音排队；断线后保留已确认文字，由用户主动重新开始，不重放旧音频。
