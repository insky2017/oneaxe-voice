## 已有能力及边界

- 服务端固定 `127.0.0.1:8097`、单 worker：`/home/sky/tools/oneaxe-voice/bin/serve:5-7`。HTTP 强制 loopback 来源与 Bearer：`/home/sky/tools/oneaxe-voice/oneaxe_voice/server.py:26-50`。WebSocket 独立执行同类检查，并拒绝带 `Origin` 的浏览器连接：`server.py:170-180`。因此手机通过 Tailscale 地址直接调用会失败；把 Uvicorn 改为 `0.0.0.0` 仍会被应用层 403 拒绝，也扩大暴露面。配置和 CLI 同样限制客户端 URL 为本机 HTTP：`config.py:50-55`、`cli.py:32-42`。
- 现成短音频 API：`POST /api/dictation/transcribe`，multipart `file`，返回 `text`、`request_id` 等；`POST /api/dictation/warmup` 可预热，`GET /api/dictation/status` 可查实际状态：`server.py:119-122,240-286`。输入为 PCM16 WAV，0.1-60 秒、8-48 kHz、1/2 声道、最多 12 MiB：`audio.py:26-44`；客户端最好统一采集 16 kHz 单声道，免去服务端重采样。无须从手机安装模型，GPU 推理留在运行 Voice 的主机。
- 桌面稳听的 VAD 和顺序语义可以作为移动端规格：20 ms PCM 帧、240 ms 预卷、默认 700 ms 静音切段和 15 秒强制分段、停止时补尾：`vad.py:10-12,93-182`；默认一轮最长 900 秒、队列 8：`desktop.py:33-37`；一个消费者串行上传并按完成顺序追加原始 ASR 文本：`desktop.py:345-370,391-413`。队列满时停止采集、保留刚形成片段并排空，而非丢段：`desktop.py:353-370`。口头语整理已明确暂缓：`AGENTS.md:8`。
- 现成 WS `WS /api/dictation/stream` 仅支持 `qwen-stream` 或 `r2t2`，非 `vad`：`server.py:170-190`。协议是 16 kHz、单声道、PCM16 小端二进制块（至多 64000 字节），文本控制帧 `flush`、`keepalive`、`finish`、`cancel`；总音频最多 60 分钟，30 秒无应用消息则断开：`server.py:193-236`。仅一个活跃流会话，整轮占用引擎；期间短 WAV 请求/预热/模式切换会忙碌：`docs/api.md:123-135`。`text` 是稳定文字，`pending` 是候选，不应自动输入：`docs/api.md:127-137`。
- 桌面采集使用 PulseAudio/PipeWire 的 `parec`，DJI 麦克风设备选择：`capture.py:20-40,78-85`。自动输入依赖 X11 `xdotool`/`xclip` 并核对原窗口焦点：`paste.py:24-32,54-89`。这两部分不能直接移植到 Android。现有公开 API 不提供手机远端录音控制、IME 提交或设备级鉴权；`docs/architecture.md:65-69` 也明确远程服务和多用户调度尚未实现。

## 原接入顺序（历史建议，API 路线待重新审核）

1. **V1 稳听**：Android `AudioRecord` + 前台录音服务，做麦克风权限/设备路由、20 ms PCM 帧 VAD、有界队列和停止补尾；每段封装为 16 kHz mono PCM16 WAV，串行调用短录音 API。主机模型预热与录音可并行。收到 429 时按 `Retry-After` 有界重试；401、403、413、422、503 要给出明确状态并停止或保留待确认草稿，不应盲目无限重试。录音和队列只在工作会话中保留，持久化转写需用户选择。服务端已有模型互斥与 429/503：`server.py:240-286`。
2. **V2 流式**：等 V1 的安卓前台服务、断网恢复、焦点与输入保护验收后，再接 WS。它适合实时字幕和更低可见延迟，但一次连接长期占 GPU 锁、只有一个手机/桌面会话能用；切换网络、Android 后台限制、WS 中断、`flush` 与 `finish` 的幂等和稳定文本去重都要单独处理。桌面实现为逐块送音频、等待响应、每 10 秒静音保活，并只发送冻结文本差量：`desktop.py:483-537`。V1 的短段 HTTP 更适合先证明手机端可靠性和多设备公平性。
3. **输入层**：先支持应用内草稿、复制和 Android Sharesheet，让用户明确选择目标。需要跨应用直接听写时，独立实现 Android IME，通过当前 `InputConnection.commitText` 提交稳定增量；会话绑定焦点，目标/选择区变化、IME 失活或网络重连后转为“仅复制/草稿”，防止重复及误投。终端场景默认只插入文字，不附带 Enter；转写内容应做控制字符和换行规范化。桌面当前也仅在原窗口匹配时自动粘贴：`paste.py:35-38,70-89`；Android 不能沿用 X11 路径。IME 不应伪装系统全局键盘事件。

## 手机到主机的安全连接

**原短期验证设想（未实施）**：手机在 Tailnet 中通过 SSH 到主机，Android 侧仅在 `127.0.0.1` 打开本地端口并转发到主机 `127.0.0.1:8097`。服务仍看到主机 loopback 地址，但此方式需要手机持有主 Bearer，不能提供新要求的手机权限隔离，已不适合作为当前接入方案。实际完成过的实验是 USB ADB reverse 加临时代理，主 Bearer 留在主机；正式 Tailnet 路径尚未部署。

**正式配对候选（待审核）**：主机侧轻量移动入口保管主 Bearer，手机持独立可撤销设备凭据，通过 Tailnet 上的受控 SSH 转发或其他已审定传输访问。只允许受限状态查询与“使用当前已加载模型”识别，不开放预热、选型、卸载和策略管理。接口白名单不能消除上游转写的隐式切换，必须先解决模型权限契约，不能把直接转发当前 API 当作完成。主机身份校验、设备认证、权限绕过、取消/断线不干扰 PC 都需验收；完整 SSH 与凭据细节在选型后确定。本轮不部署入口、不改解析服务端。

**多设备/GPU 竞争**：当前 OneAxe Voice 是单 GPU worker，短段、预热、流式共享互斥；流式整轮排他。手机与桌面同时听写会收到 429，设备增加后不能靠每端无限重试解决。V1 先显示“识别服务忙碌”、有界等待/取消；主机代理需按设备限流与总并发控制，并定义桌面录音优先级。长期要在主机统一排队或另开资源预算，不能在手机侧承诺并行实时识别。GPU 不可用返回 503，不能默默切 CPU：`docs/architecture.md:45-53`、`AGENTS.md:12`。

## 接入验收清单

- Android 8+ ARM64 目标机实测麦克风授权、前台服务通知、息屏、音频焦点/来电、蓝牙/有线/内建麦克风切换；确认系统中断后麦克风释放。
- 主机服务状态、手机 Tailnet/SSH 连通、端口仅 loopback、主机密钥校验、设备配对/撤销/丢机处理；任一认证层失败时不得上传音频。
- PCM/WAV 格式、0.1 秒与 60 秒边界、12 MiB 上限、静音、中文/英文混合、长句强制切段、700 ms 停顿、队列满、停止补尾；逐段序号和最终文本无丢失、重复或乱序。
- 断网发生在录音、上传中、收到结果后但提交前、提交后四个时点；验证无重复提交、保留可恢复草稿、取消后无后续输入。多手机与桌面同时提交，验证 429、`Retry-After`、队列上限和 GPU 503。
- IME 目标切换、光标/选区变化、终端输入、密码框、剪贴板回退；仅稳定文本能提交，终端不发送 Enter，`pending` 不入目标应用。WS V2 另测静音 keepalive、`flush`/`finish`、60 分钟限制和网络切换。
- 证据按源码、单元/模拟、真机、主机 API、实际跨设备端到端分层记录；本次仅确认源码边界、现行服务 active/loopback、`/health` 200，没有 Android 真机或经 Tailnet 的端到端验证。
