# Voice Lab 真机验证记录

**历史记录说明（2026-10-02）：** 以下是旧 USB 实验当时的证据。用户现要求仅经 Tailnet 直连，手机不得隐式切模型；旧转写路径已停用，文末的恢复建议已失效，请按 [当前说明](../README.md) 操作。当前连接配置验证另见 [2026-10-02 记录](tailnet-settings-e2e-2026-10-02.md)。

日期：2026-10-01。设备：Pixel 9 Pro XL，ADB serial `47151FDAS0002J`。范围仅为独立实验 APK `com.oneaxe.pocket.voicelab`，不代表 Pocket 主 App 的语音功能已集成。

## 环境与边界

- 安装前手机没有 Voice Lab 包；启用前 `enabled_accessibility_services` 为空字符串。测试中仅启用 Voice Lab 的辅助功能，结束后应只关闭该项并复查原值。
- 麦克风权限已授予。电脑端主 Voice Bearer 仅在电脑；手机导入临时 lab token，经 USB `adb reverse tcp:18097` 访问主机 `127.0.0.1:18097` 的受限代理。主机转发前核对桌面 Voice 为 `idle`。
- 手机和电脑可能被同时使用。每次写入前应核对当前焦点、原输入框内容和光标；真机测试不应写入 Termux、微信等非测试目标。

## 结果

| 测项 | 结果与证据层级 |
| --- | --- |
| 独立 APK 安装、页面、麦克风与辅助功能 | 已在真机确认；48 dp 悬浮按钮可见。这只证明安装和授权。 |
| 原用户真人听写 | 首次只得到“嗯。嗯。”；当时主机收到 3 次转写并返回 HTTP 200。原音频未保存，不能断定唯一根因，也尚未用同一真人语句复测。 |
| 旧切段门限分析 | 原门限帧 RMS 650；公开 `quiet.wav` 的最高帧 RMS 635.34，421 帧中没有一帧过门限，因此旧代码必定丢掉该样本。主机单独转写该完整音频成功。详见 `fixture-baseline-2026-10-01.json`。 |
| 修订后的公开样本 `normal.wav` | 手机导入 8.41 秒 PCM，切为 3 段、3 次 HTTP 200，原测试输入框追加了三句。 |
| 修订后的公开样本 `quiet.wav` | 手机导入相同内容的弱音版本，切为 3 段、3 次 HTTP 200，原测试输入框追加了三句。 |
| 修订后的公开样本 `silence.wav` | 3 秒静音，`segments=0`，不发转写，原输入框内容不变。 |
| 句间空格 | 初版按段追加英文句子时缺空格；最新构建在自环录音的三句追加中已确认句间有空格。 |
| 麦克风采集与自环回放 | “播放样本并录制”从手机扬声器播放 `normal.wav` 并使用 `VOICE_RECOGNITION` 采集。导出的 WAV 为 16 kHz、单声道 PCM16、8.98 秒，RMS 567.11、peak 4759，142140/143680 个 sample 非零、0 clipping。回放按钮实际点击，Android `dumpsys audio` 记录该 App MediaPlayer 于 23:24:25 started、23:24:34 stopped/released，输出 deviceIds:[3]。这证明采集与播放器运行，不代表真人听写或 ASR 已通过。 |
| 自环录音送 ASR 与原输入框 | 通过本轮链路：8.98 秒录音经手机切为 2.66 / 3.12 / 1.88 秒三段，末段为 stop；三次 HTTP 200，原框依次出现完整三句，无 Enter。实际第一句将 phone 识别为 film，其余两句完整；链路通过不代表识别准确率 100%。见 [结构化证据](loopback-e2e-2026-10-01.json)。 |
| 中文样本 | 既有 Voice 文档中的 10 秒中文验证 WAV 经手机切段、HTTP 200 后，原输入框完整显示“大家好，今天是二零二六年九月二十六日，丙午年。”；无 Enter。见 [结构化证据](chinese-e2e-2026-10-01.json)。 |
| Chrome 普通/密码输入框与 Termux | 尚未验收。自定义终端控件的辅助功能写入兼容性未知。 |

## 复现和留证

最终实验 APK SHA-256：`d70ac0f6c8af8dd245b49d3137eb2f9d34fa118e9735d21d9337772f10dcd3fa`。自环成功轮请求 ID：`9bbaf657-14eb-4f8e-bd15-7e9d4141d6dc`、`74ebe8e9-1823-4955-859c-3d24e172aa57`、`ee4e98a0-7d6e-4a2d-bd52-f999c15a491a`。

保留一次测试干扰：首轮自环转写期间立即运行 `uiautomator dump`，只观察到首段 HTTP 200、未写入；不将该轮标为通过。避免处理期间启动 UIAutomator 后重跑，三段均完成并写入。用 `logcat` / `screencap` 观察运行中的辅助功能，等转写结束后再读取 UI 层级，避免 UIAutomator 对辅助功能生命周期造成干扰。

公开样本可由 `python3 tests/generate_fixtures.py /tmp/oneaxe-voice-fixtures` 生成。将样本导入手机时使用 `adb push FILE /data/local/tmp/voice-lab-fixture.wav`，再运行 `adb shell run-as com.oneaxe.pocket.voicelab cp /data/local/tmp/voice-lab-fixture.wav files/fixture.wav`。曾用 `adb exec-in ... tee` 导入 269164 字节 WAV，实际仅写入 12285 字节，故不能用该方式判断切段质量。

录音检查页每次保存为 `cache/record-check-<random>.wav`，离开页面会删除。导出前先通过 `run-as ... ls cache` 找本轮文件，使用 `adb exec-out run-as ... cat cache/文件名`；固定名 `record-check.wav` 不存在的报错只是导出路径错误，并非录音失败。自环录音文件仅为临时诊断数据，不应提交或输出内容；保留以上采样统计即可。

当前切段使用 20 ms 帧、实验门限 RMS 50、约 700 ms 静音结束和停止补尾，并记录不含音频/正文的帧数、切段及 HTTP 状态。50 是弱音样本可通过的实验值，尚未经过多设备噪声、真人弱音和误触发评估；还未移植桌面 WebRTC VAD。修复降低了已复现样本被过滤的风险，不能由此宣称原真人失败已解决。

## 调试结束状态

已核对手机安装 APK 的 SHA-256 与上述最终构建一致。实验代理已停止，18097 / 18098 均无监听，ADB reverse 已移除；只关闭了 Voice Lab 辅助功能，启用列表恢复为空。手机及主机上的自环原始录音、手机导入样本已删除，仅保留采样统计和公开测试文字证据。USB 常亮恢复原值 0，`oneaxe-steadyflow-thsauto.service` 恢复 active/running；OneAxe 主网络 VPN 仍为活动 VPN。

实验 APK 保留安装。“录音检查与回放”独立可用，无需主机服务；手动点击开始才录音，离开页面删除录音。语音转写本轮只通过 USB 临时代理验证，恢复使用需按 README 重新启动代理、配对和启用悬浮服务，不代表已完成远程 Tailnet 语音接入。真人复验、Chrome / Termux、噪声环境及完整 V01–V03 仍未验收。
